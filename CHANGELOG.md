# Changelog

All notable changes. Versions follow semantic versioning; the project layout has its own number (see docs/LAYOUT_V1.md).

## 0.1.1 (2026-10-26)

- Python 3.9 works again. `wr_init`, `wr_install` (and so `wr_update`) and `wr_migrate` wrote files with an option that only exists from Python 3.10, so on 3.9 they stopped with `TypeError: write_text() got an unexpected keyword argument 'newline'`. They now write the same bytes in a way 3.9 supports. Nothing else changed.

## 0.1.0 (2026-10-26)

First portable build.

- 14 skills replace the legacy agents and commands: `writing-room` (router and runtime), `create-world`, `create-style`, `story-status`, `promote-chapter`, `writing-assistant`, `world-archivist`, `story-ideator`, `outliner`, `planner`, `draft-writer`, `reviewer`, `draft-fixer`, `story-analyzer`.
- Scripts are Python only and optional; every skill has a way to work without a shell. Added `wr_init`, `wr_migrate`, `wr_doctor`, `wr_resolve`, `wr_next`, `promote_chapter`, `wr_install`.
- Project layout v1 is unchanged; existing projects work without migration.
- Installer for Claude Code, Devin, OpenCode and Hermes Agent, at project level or user level (`--scope`, `--user`); one copy where tools share a folder; warns when the project is not the repository root that Hermes and Devin look in; Claude Code plugin manifest.
- Skill descriptions are double-quoted (unquoted `: ` made the YAML invalid and Claude Code dropped the metadata).
- File listings are sorted case-insensitively so output is identical on Windows, macOS and Linux.
- Licensed under MIT. The sample world and stories are generated by `tools/build_sample.py` and are invented for this project; no private fiction is included, and `tools/check_public_clean.py` checks for it.
- `wr_doctor` checks consistency between files, not just layout: a world without `SUMMARY.md` or `WORLD_ORDER.md`, a `SUMMARY.md` whose names differ from the entity files (by name, not count; case and underscores ignored), a story missing from `WORLD_ORDER.md` or a row naming a story that does not exist, a completed story with no snapshot, promoted chapters with no Timeline entry. Each warning names the skill that fixes it, and the router relays them. Fixture-coverage hints moved out of the doctor into `tools/check_layout_v1.py`.
- `wr_update.py` updates installed skills when a new build exists: replaces changed skills, adds new ones, removes dropped ones, saves locally edited skills first, shows the changelog since the installed version, reports (and with `--guidance` replaces) customised AGENTS.md/CLAUDE.md, refuses downgrades and newer project layouts, supports `--check`/`--dry-run`, project, user and explicit targets, and updating from an installed copy. The install manifest now records a content hash per skill.
- `wr_migrate.py` ignores the installer's skills folders when checking for uncommitted changes, so installing first and migrating second works in a git project. `wr_migrate.py --retire-legacy` moves the old framework files of a legacy project (agents, commands, scripts, rules, README, CLAUDE.md) to `.writing-room-legacy/` (reversible; user content and templates are never touched) and adds `AGENTS.md`/`CLAUDE.md`; `wr_doctor` warns while they are still there. Guide: docs/MIGRATING.md.
- Documentation: README, user guide, pipeline reference, file formats, skill-writing guide, install guide, release checklist. CI runs the lint and the tests on Windows and Linux (Python 3.9, 3.11, 3.13).
- `CONCEPT.md` may carry frontmatter (`world:`, `status:`) that mirrors the body `**World:**` and `**Status:**` lines so Obsidian Bases can group stories by world. The concept template has it; the outliner, planner and router keep `status:` in step; `wr_doctor` warns when it differs from the body. Optional: concepts without it work unchanged. `wr_init` also copies `Stories.base`, a Bases table of the stories grouped by world with links to each story's concept and outline.
- `tools/export_public.py` publishes the tree as a fresh one-commit repository (optionally tagged) after checking for private names, and with `--update` adds a later release to the public repository as one tagged commit; `tools/check_public_clean.py` checks files and history.
- `load_bible.py` can be used as a library: `collect()` returns the context items (with their source file and tier) and `render()` gives the exact text the command prints. Output is unchanged. `common.py` gains `read_exact`, `in_project` and `snapshot_lookup`.
- The Writing Room harness (a runner for the chapter pipeline on a local model) moved to its own repository, `writing-room-harness`. It uses the installed skills, so `load_bible.collect()`/`render()` and the other script functions it imports are now an interface another project depends on.
- The deprecated `reviewer-consistency` and `reviewer-character` agents are gone; `reviewer` does both passes.
