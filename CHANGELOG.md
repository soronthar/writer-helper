# Changelog

All notable changes. Versions follow semantic versioning; the project layout has its own number (see docs/LAYOUT_V1.md).

## 0.2.0 (2026-11-09)

- "What's next?" / "where am I?" is answered by the `writing-room` router, which reports each story's next skill from `wr_next` and stops without starting it. `story-status` no longer claims those questions in its description; it is for the full dashboard only, which reads far more files. `wr_next` prints `next skill: none — …` instead of `— — …` for a finished story.

Fixes from a review of a long local-model run (OpenCode against a local LLM).

- `load_bible.py`: an entity file placed directly in `state/bible/` (outside its type folder) is never read, as before, but now a ⚠ notice names it ahead of the copy that was loaded instead. `wr_doctor` reports such files as errors (`state/bible/DESCRIPTION.md` is still fine).
- `wr_doctor`: a Book's chapter rows marked Complete in `WORLD_ORDER.md` no longer trigger "Complete at position N but there is no snapshot". It warns only once the book is finished (Complete chapter rows reach OUTLINE.md's Total chapters, the story-analyzer's rule), and then about the snapshot at the book's first row.
- `query_position.py`: for a story that follows a Book (one row per chapter), `before` is now the Book's first row, where its snapshot is made, instead of its last chapter row, where none exists. Stories after a Book now load the Book's snapshot as their world baseline instead of falling back to the current world. The planner's no-shell lookup and the analyzer's snapshot step say the same.
- `load_bible.py`: a `--style` hint that matches nothing no longer loads the only style file anyway; it reports that nothing matched.
- Temporary working files have one place: `.writing-room-work/` at the project root, with paths inside mirroring the project (`stories/<Story>/…`, `worlds/<World>/…`). It is created on demand with its own `.gitignore`, is never read as state, and can be deleted at any time. The shared conventions say to use it for saved loader output and for drafting large documents before writing them to their real place.
- `load_bible.py --output` and `load_world.py --output` save the context there as UTF-8 (`--output <file>` still picks a path, relative to the project root) and print only a receipt: the file's absolute path, then each item with its line range (and, for `load_bible`, its source). For harnesses that cut off long output or re-encode shell redirection; the absolute path means it no longer matters which folder the command ran from.
- `story-analyzer`: loads entities with the story's `--position` baseline (it read the master world before, unlike the planner, draft-writer and reviewer), and writes `state/bible/` copies from exactly the file it loaded, snapshot included. Steps are now in order: apply story state (Step 8), then hooks (Step 9), with one approval gate in every mode before anything is written to `HOOKS.md`, including status changes. The report says proposed / approved / excluded.
- Chapter plan template: each scene has `Scheme / fact dispositions` and `Notes for Draft Writer` fields, and Style Directives has a `Length` field. The planner's word-count check accepts a Length override with a reason and authority; its continuity check uses the Timeline and entity states rather than chapter prose it is told not to load.
- Review templates: every issue has `Author decision required`, and each report lists `Sources loaded`. The draft-fixer treats any request for author confirmation as a Verify item.
- `reviewer`: each report is written as soon as its pass ends — `Reviewer-Consistency.md` after the consistency pass, `Reviewer-Character.md` as a checkpoint after the plan check and in full after the character pass — instead of both at the very end. Reports carry `**Review status:** Complete | In progress — …`, and a re-run resumes after the last finished pass instead of starting from scratch. Starting over marks old reports `In progress — being redone` first. `wr_next`, the router and `story-status` send a partial review back to the reviewer, and the draft-fixer stops on one unless the user says otherwise. Reports without a status line (older versions) count as finished. The character template gains the Plan Violations section the skill already required.
- Default Style: one POV character per chapter, with no shifts (it also allowed shifts "at section breaks" while forbidding section breaks). Typical Length is listed as overridable, POV per Chapter as not. `create-style` stops on the same contradiction.
- `load_bible.py --for <preset>`: one preset per skill step (`planner`, `draft-writer`, `reviewer-consistency`, `reviewer-character`, `draft-fixer`, `story-analyzer`) sets the flags that step needs. With a preset, or without `--world`, the script works out the world from CONCEPT.md (the series CONCEPT.md for a Book), the baseline `--position` from WORLD_ORDER.md (the same lookup as `query_position`), and the planner's `--structure` from CONCEPT.md. It also reads `--story "<Story>"` as `stories/<Story>`. A CONTEXT block at the top of the output says what was used and where from. `--position none` turns the baseline off, and `--recipes` prints every preset with the long-form flags it stands for. The skills' 6–10-line bash commands, with `\` continuations and `[optional]` brackets that local models copied literally, are now one line each. The long form (`--world` given, no `--for`) prints exactly what it did before.
- `load_world.py --for story-ideator` and `--for outliner`: each skill step's world files in one call. The ideator preset is the overview plus a SUMMARY CHECK, which compares SUMMARY.md with the entity files the way `wr_doctor` does. When SUMMARY.md is missing or stale, the same call loads every entity file, so the check is no longer counted by hand. The outliner preset takes the world and structure from CONCEPT.md and adds `WORLD_ORDER.md`. New `--trope` and `--archetype` flags load craft files alongside `--entity`, and `--world` accepts a bare world name. The `story-ideator` loads the world right after the world is confirmed (Step 2b), then loads every entity and craft file it needs in one more call. The `outliner` needs one call, plus one for factions it finds through SUMMARY.md. Both had read these files one at a time. All loader commands in the skills are one line. Without `--for`, output is unchanged.
- `story-ideator`, after a long local-model run where the session lost its earlier context and then saved a concept nobody approved:
  - `load_world.py --for story-ideator` prints `GUIDE.md` and `Format Reference.md` in full but only the Overview of each structure file (about 500 lines for the sample world instead of 1,240; the eight full files are about 25,000 tokens). `--structure "<Name>"` alongside `--entity`, `--trope` or `--archetype` adds the full file of the chosen structure to the follow-up load. The plain overview form is unchanged.
  - The approved concept is saved at once to `.writing-room-work/worlds/<World>/CONCEPT.md` (Step 4C), and everything after is built from that file. A session that loses track resumes from it instead of rebuilding the concept from memory.
  - New `new_story.py --world --story [--hook]... [--position N]` does the bookkeeping in one call: it copies the saved concept to `stories/<Story>/CONCEPT.md` with its title, creates the folders and the three `state/` skeletons from the templates, adds the WORLD_ORDER.md row (Unit from the concept's Format) with its `Last synchronized` line, and sets hooks to `In Use (<Story>)`. It checks everything first and changes nothing when the story exists, the concept still has placeholders, the Format or World is wrong, or a hook is not in HOOKS.md. Hand edits of the WORLD_ORDER.md and HOOKS.md tables were where the run failed repeatedly.
  - The concept is written to that file as a draft (`<!-- draft: not yet approved -->` on its first line) the first time it is previewed, and each change goes into the file before it is shown. On approval the line is deleted; `new_story.py` refuses a file that still has it. Step 1 now checks for the file: a new session can continue a draft or an approved concept instead of starting over.
  - One question round: mode, format, constraints, hook titles and structure names are asked together (Step 3), after the world is loaded. A world named in the request counts as confirmed.
  - The ideator no longer creates world elements or regenerates SUMMARY.md itself. It marks them `New — to be created`, lists them in Open Questions and the structured output, and the next step names `writing-assistant`.
- New `world_order.py` changes WORLD_ORDER.md rows in one call — `add`, `status`, `move`, `renumber`, and `chapter` for the story-analyzer — keeping the table sorted, unchanged rows byte for byte and the file's line endings, and updating `Last synchronized`. It refuses, and changes nothing, on an ambiguous or missing row. `new_story.py` uses it. The story-analyzer (step 8e) and the world-archivist (Operation 2) run it instead of editing the table by hand; their manual steps remain for sessions without a shell.
- `story-analyzer` step 8e: a Short Story or Novelette's `Full Story` row became `Complete` after its first analyzed chapter, so step 8f took the world snapshot mid-story. The row is now `In Progress` until the last chapter (OUTLINE.md's Total chapters), and a Book's Ch. 1 filling a `TBD` row is `Complete` like every other chapter (it was `In Progress`, so the book never counted as finished). `world_order.py chapter` prints `Story complete: yes|no`, which 8f uses.
- Project `AGENTS.md`: the opening said "you stay in the author's seat and make the creative decisions", which agents read as addressed to them and then could not tell whether to decide or to ask. It now says the user is the author, and a new first rule says which decisions are the user's, when the agent may choose (then present for approval), and to ask when a skill does not say.
- The draft-fixer can be interrupted safely. It edits `CONTENT.md` in place but wrote its log only at the end, so a session that stopped partway left a half-fixed chapter with no record, a rerun reported the fixes already applied as "passage not found", and the author's decisions had to be given again. It now backs up the unfixed draft to `.writing-room-work/…/Chapter_NN.before-fixes.md` and writes the log from the first fix, with a new `**Fix status:** In progress` line and a Fix Plan table updated after every fix and decision. A new session resumes from the first pending row, reusing the recorded decisions and recognising fixes that landed before the log was updated, or starts over from the backup. `wr_next.py` and the router send a log still `In progress` back to the draft-fixer; logs without a status line count as finished.
- The draft-writer no longer loses a chapter to an interruption. It held the whole chapter in the conversation until the end, so a session that stopped during the self-check lost everything. Each scene is now saved to a working draft under `.writing-room-work/` as soon as it is written (or approved, scene by scene), with a progress line; the self-check reads and corrects that file; `CONTENT.md` is assembled from it and the working draft is deleted only after `CONTENT.md` is read back complete. A new session offers to resume from the next scene, or from the self-check, and `wr_next.py` reports the saved draft.
- Skills no longer make the model work out where the framework is. `../writing-room/…` was read as relative to the running skill by some models and as a folder of the project by others. The project's `AGENTS.md` now carries a "Writing Room paths" block naming `<WR>` (project-relative for a project install, absolute otherwise), the conventions, the scripts, where templates and craft files come from, and where each skill's own references are. `wr_install.py`, `wr_update.py` and `wr_init.py` keep it current and change nothing else in the file; new `wr_paths.py` writes it by hand. `wr_doctor` warns when the block is missing and reports an error when it names a folder that is gone. Every skill now writes `<WR>/…` and opens its Files section with the same definition, including the template fallback; the lint rejects `../` paths and checks that each `<WR>/…` path exists. `wr_update` ignores the block when comparing AGENTS.md with the shipped version.
- Example names in skills are marked as invented. Some models read the writing-assistant's naming examples (`worlds/Aethermoor/`, `characters/Mara Quill.md`) as files of the bible and tried to open them. The naming rules now use placeholders, sample blocks say their names are invented, and the conventions say never to look for example names in the project.
- Old template copies no longer hide the framework's. A project migrated from the single-folder Writing Room kept the old framework's `templates/` (and often its story structures), and a project copy always wins, so the skills filled in a chapter plan without the Length or per-scene disposition fields they require. New `wr_templates.py` sorts the project's template and craft files into older than the framework's, the same, or edited, using the fingerprints of every shipped version in `shared/template_history.json` (kept current by `tools/record_templates.py`; a test fails if a changed template is not recorded). `--retire` moves the unedited ones to `.writing-room-legacy/`. `wr_doctor` warns about them, `wr_update` notes them, and `wr_migrate --retire-legacy` now moves them too, keeping the templates you edited. The conventions tell the agent to use the copy that resolves and to point the user at `wr_templates.py`.
- Shared conventions: verification claims name a file loaded in this run, otherwise "not checked"; Autonomous modes never skip author gates. Skills with a mode prompt use the mode the request already names.

## 0.1.1 (2026-10-26)

- Python 3.9 works again. `wr_init`, `wr_install` (and so `wr_update`) and `wr_migrate` wrote files with an option that only exists from Python 3.10, so on 3.9 they stopped with `TypeError: write_text() got an unexpected keyword argument 'newline'`. They now write the same bytes in a way 3.9 supports. Nothing else changed.

## 0.1.0 (2026-10-26)

First portable build.

- 14 skills replace the legacy agents and commands: `writing-room` (router and runtime), `create-world`, `create-style`, `story-status`, `promote-chapter`, `writing-assistant`, `world-archivist`, `story-ideator`, `outliner`, `planner`, `draft-writer`, `reviewer`, `draft-fixer`, `story-analyzer`.
- Scripts are Python only and optional; every skill has a way to work without a shell. Added `wr_init`, `wr_migrate`, `wr_doctor`, `wr_resolve`, `wr_next`, `promote_chapter`, `wr_install`.
- Project layout v1 is unchanged; existing projects work without migration.
- Installer for Claude Code, Devin, OpenCode and Hermes Agent, at project level or user level (`--scope`, `--user`); one copy where tools share a folder; warns when the project is not the repository root that Hermes and Devin look in; Claude Code plugin manifest.
- Skill descriptions are double-quoted (unquoted `: ` made the YAML invalid and Claude Code dropped the metadata).
- File listings are sorted case-insensitively so output is identical on Windows, macOS and Linux.
- Licensed under MIT. The sample world and stories are generated by `tools/build_sample.py` and are invented for this project; no private fiction is included, and `tools/check_public_clean.py` checks for it.
- `wr_doctor` checks consistency between files, not just layout: a world without `SUMMARY.md` or `WORLD_ORDER.md`, a `SUMMARY.md` whose names differ from the entity files (by name, not count; case and underscores ignored), a story missing from `WORLD_ORDER.md` or a row naming a story that does not exist, a completed story with no snapshot, promoted chapters with no Timeline entry. Each warning names the skill that fixes it, and the router relays them. Fixture-coverage hints moved out of the doctor into `tools/check_layout_v1.py`.
- `wr_update.py` updates installed skills when a new build exists: replaces changed skills, adds new ones, removes dropped ones, saves locally edited skills first, shows the changelog since the installed version, reports (and with `--guidance` replaces) customised AGENTS.md/CLAUDE.md, refuses downgrades and newer project layouts, supports `--check`/`--dry-run`, project, user and explicit targets, and updating from an installed copy. The install manifest now records a content hash per skill.
- `wr_migrate.py` ignores the installer's skills folders when checking for uncommitted changes, so installing first and migrating second works in a git project. `wr_migrate.py --retire-legacy` moves the old framework files of a legacy project (agents, commands, scripts, rules, README, CLAUDE.md) to `.writing-room-legacy/` (reversible; user content and templates are never touched) and adds `AGENTS.md`/`CLAUDE.md`; `wr_doctor` warns while they are still there. Guide: docs/MIGRATING.md.
- Documentation: README, user guide, pipeline reference, file formats, skill-writing guide, install guide, release checklist. CI runs the lint and the tests on Windows and Linux (Python 3.9, 3.11, 3.13).
- `CONCEPT.md` may carry frontmatter (`world:`, `status:`) that mirrors the body `**World:**` and `**Status:**` lines so Obsidian Bases can group stories by world. The concept template has it; the outliner, planner and router keep `status:` in step; `wr_doctor` warns when it differs from the body. Optional: concepts without it work unchanged. `wr_init` also copies `Stories.base`, a Bases table of the stories grouped by world with links to each story's concept and outline.
- `tools/export_public.py` publishes the tree as a fresh one-commit repository (optionally tagged) after checking for private names, and with `--update` adds a later release to the public repository as one tagged commit; `tools/check_public_clean.py` checks files and history.
- `load_bible.py` can be used as a library: `collect()` returns the context items (with their source file and tier) and `render()` gives the exact text the command prints. Output is unchanged. `common.py` gains `read_exact`, `in_project` and `snapshot_lookup`.
- The Writing Room harness (a runner for the chapter pipeline on a local model) moved to its own repository, `writing-room-harness`. It uses the installed skills, so `load_bible.collect()`/`render()` and the other script functions it imports are now an interface another project depends on.
- The deprecated `reviewer-consistency` and `reviewer-character` agents are gone; `reviewer` does both passes.
