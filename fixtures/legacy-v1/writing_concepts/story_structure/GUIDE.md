# Story Structure — How to Use This Directory

This directory contains one file per named story structure. Each file is a planning reference — a framework that describes how stories of a certain shape tend to be built. They are not prescriptions.

---

## Files in This Directory

- **[[Format Reference]]** — Start here when a format decision is needed. Defines chapter counts, word counts, subplot capacity, POV guidance, and structural fit for Short Story, Novelette, Book, and Book Series.
- **[[The Hero's Journey]]**, **[[Three-Act Structure]]**, **[[Dan Harmon's Story Circle]]**, **[[Seven-Point Story Structure]]**, **[[Fichtean Curve]]**, **[[Freytag's Pyramid]]** — one file per named structure.

---

## What Each Structure File Contains

Every structure file has the same format:

- **Overview** — what the framework is, where it comes from, what genres or story types it suits best
- **Quick Reference table** — all stages at a glance with story position (as a percentage of the total) and one-line purpose
- **Per-stage entries**, each with:
  - `Narrative beat` — what the story does at this stage
  - `Story position` — approximate location in a full story
  - `Questions to answer` — what the Planner or Outliner must figure out for this stage before moving on
  - `Notes` — flexibility, common variations, pitfalls, and when to deviate
- **Flexibility** — which stages can be skipped, compressed, merged, or reordered

## How Each Agent Uses This Directory

### Outliner
When the user specifies (or you choose) a story structure:
1. Read this GUIDE.md.
2. Read the chosen structure file.
3. Map the structure's stages across your planned chapter count. Not every stage needs its own chapter — long middle sections (e.g. Tests, Allies, Enemies in the Hero's Journey) can span several chapters; short adjacent stages (e.g. Call to Adventure + Refusal) can compress into one.
4. Annotate your outline with the stage name each chapter covers. This gives the Planner and Reviewer-Consistency a shared reference point.

### Planner
When planning an individual chapter:
1. Read this GUIDE.md.
2. Read the structure file the Outliner used (check the outline for the stage label).
3. Identify which stage(s) the chapter covers.
4. Use the `Questions to answer` for those stages as a checklist — ensure your chapter plan resolves each question before handing off to the Draft Writer.

### Ideator
When generating story ideas:
1. Read this GUIDE.md.
2. Read the structure file you are using as a scaffold.
3. Use the stage list to generate one concrete event or scene idea per stage. This ensures the idea has a complete arc, not just a premise.
4. If the user asks you to avoid certain tropes or apply specific archetypes, use the stage list to identify *where* in the arc those elements would naturally appear.

---

## General Principle

Structure is guidance, not formula. Stages can be compressed, reordered, subverted, or skipped entirely if the story demands it. The frameworks here describe what tends to work — they do not mandate what must happen. A writer who understands the structure well enough to break it intentionally produces more interesting work than one who follows it mechanically.

When in doubt: structure serves character and theme, not the other way around.
