## Phase 0 findings worth carrying forward

- The fixture excludes `chapters.tgz` (a leftover archive) but keeps `Chapter_03_original.md` as a realistic stray file.
- The scripts resolve the project root by `chdir` to their own parent's parent. That is the behaviour Phase 1 replaces with marker/`--root`/walk-up discovery, and the golden tests run the scripts from inside the fixture to match it.
- Some older concept files have no `**Status:**` field, so Status cannot be treated as required.

## Phase 1 findings

- The first compatibility run of the new scripts passed for the wrong reason: `--scripts scripts` was a relative path, and the fixture contains its own legacy `scripts/`, so the legacy scripts ran. `tools/golden.py` now resolves `--scripts` to an absolute path, and a nonexistent scripts directory fails every case. If you add a golden case, confirm the new scripts are actually the ones running.
- Craft files (story structures, archetypes, tropes) and templates fall back to the framework's `shared/`; styles never do, because a style is the author's choice. A fresh project gets a starter style copied in by `wr_init.py`.
- `wr_migrate.py` only adds the marker. Moving or deleting the legacy framework files inside a project is deliberately not offered until the skills replace the legacy agents (Phase 2/3), because those agents still depend on them.

## Phase 2 findings (in progress)

- `tools/convert_legacy.py` does the mechanical first pass (frontmatter, `Writing_Room/` prefix, tool names, agent names to skill names). Everything else (descriptions written for auto-triggering, Next step lines, conventions pointer, script fallbacks) is done by hand, then checked by `tools/lint_skills.py`.
- The lint only inspects prose outside code fences, so shell commands inside fenced blocks are not caught; review those by hand (this is how the `cp`/`rm -rf` block in `promote-chapter` was found).
- The legacy `story-status` dashboard always showed `Reviewer-Quality ✗` for an unimplemented agent; the converted skill drops it.
- Template headings and registry names are data, not prose. `templates/story/chapter_plan.md` has headings such as `Notes for the Draft Writer`; existing plans use them, so the converter must never rename role names inside them. `convert_legacy.py` now skips "for (the) Draft Writer", and `tests/test_skills.py` (ConversionFidelity) fails if a protected phrase count drops below the legacy agent's.
- Legacy inconsistency fixed: the draft-writer's closing "Next steps" told the user to run the Story Analyzer and Reviewer in parallel and mentioned an unbuilt Reviewer-Quality. The canonical order (reviewer, draft-fixer, story-analyzer, promote-chapter) is now what every converted skill says, and a test checks the Next step chain.
- Planner and draft-writer stay single-file (about 260 lines each); no `references/` split was warranted. The big ones (`story-analyzer`, `reviewer`, `world-archivist`) will be split.
- Chapter loop complete (planner, draft-writer, reviewer, draft-fixer, story-analyzer). `reviewer` and `story-analyzer` are split into a procedure plus `references/` (reviewer: consistency-pass, character-pass; story-analyzer: analysis-rules, write-rules, preview-format, snapshot-manual), so the rules load only at the step that needs them.
- `lint_skills.py` now also checks `references/*.md`, not just SKILL.md.
- The draft-fixer used the Edit tool's requirement for exact text as a reason to read CONTENT.md directly. The portable wording keeps the substance: fixes are exact-text replacements, and a passage that does not match exactly once is skipped and logged rather than guessed.
- `create_snapshot.py` has a documented manual fallback (`story-analyzer/references/snapshot-manual.md`) whose manifest text is identical to what the script writes; check that file if the script's `MANIFEST` or `INDEX_HEADER` text ever changes.
- Heredocs with some quote and backslash combinations were rejected by the shell tool during this work; multi-line Python patches are saved to a file and run instead.
- story-ideator and outliner share one reference, skills/writing-room/references/world-loading.md (overview pass, structure pass, staleness check, entity reads, each with a no-shell path). The legacy agents duplicated this text.
- Both legacy agents had the Agent tool and called the Writing Assistant as a subagent. The skills instead say to follow the writing-assistant skill within the same session and then return, so no subagent support is needed.
- Added to outliner (not in the legacy agent): step 4e and a Step 7 instruction to fill World Order Position, Story before and Story after from WORLD_ORDER.md. The story-ideator already told the outliner to do this, but the outliner never said how, so the fields were filled by chance.
- Converter protections extended: the WORLD_ORDER row note "Placeholder — expand after Outliner" and the output label "Flags for the Planner" are data/labels and are no longer renamed.
- story-ideator step 6 had a leftover self-correction ("Actually, ... you can skip this call"); it is now a plain optional step.

## Phase 3 (2026-10-02)

- Router: skills/writing-room/SKILL.md rewritten. It finds the project, runs wr_next (or applies the same ten-rule list from the files when no shell is available), hands off by following the named skill inline, and re-checks after every skill. It also owns "Finishing a story", the duty the legacy Head had: set CONCEPT Status to Complete after the last chapter (with confirmation), offer consolidation, never set Archived automatically.
- wr_next.py is new. It reads only files and applies the pipeline rules; `recommended` is set only when exactly one story is in progress. Consolidation is detected by a `### [[Story]]` heading in the world's TIMELINE.md. It flags a real inconsistency seen in older projects: every chapter promoted and consolidated but CONCEPT Status still Active (covered by a test that edits a copy of the sample).
- tests/test_loop.py walks a project through concept, outline, two full chapter cycles, completion and consolidation, asserting wr_next's answer at all 16 steps. This is the nearest thing to the exit criterion ("a fresh session can run the whole loop from the router alone") that can be checked without a model; the real check is the smoke test (Phase 7).
- AGENTS.md: two audiences, two files. skills/writing-room/shared/project/AGENTS.md (with a CLAUDE.md that imports it) is what an author's project gets, via wr_init (never overwriting, --no-guidance to skip). The repo-root AGENTS.md is the contributor guide. wr_migrate does not add guidance files to legacy projects; the Phase 4 installer will offer that.
- The deprecated reviewer-consistency and reviewer-character agents have no skills; a test asserts they do not exist and the router tells users the merged reviewer replaced them. The legacy copies remain in fixtures/legacy-v1 only.

## Phase 4 (2026-10-02)

- wr_install.py: one copy per distinct folder. Claude Code's `.claude/skills` is read by Devin and OpenCode as well, and `.agents/skills` by Devin and OpenCode, so `--harness all` at project scope installs `.claude/skills` plus Hermes, not four copies that would clash. Copies only (no symlinks), per-folder manifest `.writing-room-install.json`, never replaces a skill folder it did not install without `--force`, `--dry-run`, `--list`, `--uninstall`, `--guidance` (adds AGENTS.md and CLAUDE.md to a project if absent, which is also how legacy projects get them).
- Harness locations were re-checked against each tool's own docs on 2026-10-02. New fact: Devin's user-level folder is `~/.config/devin/skills` (Windows `%APPDATA%\devin\skills`), and Hermes supports `skills.external_dirs`. Both are in docs/INSTALL.md.
- The runtime-in-skill layout (D9) paid off: the installed copy is self-contained, and a test runs the golden comparison, the doctor, the cross-skill lint and the template lookup against the installed copy.
- shared/skills.json is the list of skills the doctor expects to find next to writing-room (a test keeps it equal to the skills folder). VERSION holds the version the installer records and plugin.json repeats (a test keeps them equal).
- Real bug found by `claude plugin validate`: unquoted descriptions containing `: ` (for example "Status: Concept") are invalid YAML, and Claude Code then silently drops all of that skill's metadata. All 14 descriptions are now double-quoted. The lint requires it, and the converter writes quoted descriptions. The previous lint parsed frontmatter loosely and could not have caught this.
- Real bug found by running the suite on Linux (WSL Ubuntu, Python 3.12): file listings were ordered by Path comparison, which is case-insensitive on Windows and case-sensitive elsewhere. `md_files` now sorts case-insensitively (matching what the Windows-recorded golden output expects), and the golden digest sorts the same way. 100 tests pass on both platforms.
- macOS was not tested. Windows paths were tested with Python 3.11 only; Linux with 3.12 only; 3.9 remains untested.
- Still unverified (smoke tests, Phase 7): that each real agent finds and triggers the installed skills, Devin cloud-session script execution, Hermes AGENTS.md handling.

## Updating an instance (2026-10-02)

- Requirement: a script to update an installed instance when a new version is built. `wr_install.py` re-run already replaced our folders, but it did not know what was installed, removed nothing a new build dropped, ignored local edits and reported no changes.
- `wr_update.py` is run from the new build and finds installs by their `.writing-room-install.json` manifests (project folders for the four agents, `--user` folders, explicit `--target`). Per install it plans (add, update, remove, unchanged, conflicts), saves locally edited skills to `.writing-room-backups/<time>/` beside the skills folder (not inside it, so no agent loads the backup as a duplicate skill), applies, and rewrites the manifest.
- Edit detection needs a record of what was installed, so the manifest now stores a content hash per skill folder (paths plus bytes, ignoring `__pycache__` and `.pyc`, which running an installed script creates). Installs made before this change have no hashes; for them everything replaced or removed is backed up, which is conservative and says so in the output.
- Content, not just version, decides whether an update is needed, so a rebuild of the same version number still updates (development builds), and a hand-deleted skill folder is restored.
- Safety rules mirror the installer: only folders the manifest lists are ever changed or removed; a new skill colliding with a foreign folder is skipped and reported (`--force` to replace); downgrades and projects with a newer layout are refused; project content is never touched. AGENTS.md and CLAUDE.md are reported if they differ from the shipped version and replaced only with `--guidance`, keeping a `.bak`, because users customise them.
- Layout migrations: none exist (layout 1 only), so an update never migrates content. The layout check is the hook: when a build understands a newer layout it will carry a migration and the updater will refuse older projects until it has run.
- `wr_install.py` was refactored around a `Source` object (a skills folder with its names, version, hashes, layout), shared by both scripts, so a build other than the one next to the script can be used (`--source`), including from an already-installed older copy.
- Tried on the author's cutover copy: dry run reported exactly one changed skill (the runtime, which had gained scripts since that copy was installed) and that the install predates edit tracking.

## Doctor reports file inconsistencies (2026-10-02)

- Found by the author running the real flow in OpenCode: the agent noticed by itself that two of the three worlds had no `SUMMARY.md` and no `WORLD_ORDER.md`, and asked whether the doctor should say so. It should: the layout spec called both files optional, so the doctor only checked a `SUMMARY.md` that existed, yet the skills depend on both (world-loading, position lookups in the planner and outliner, story-ideator's world-order step). "Optional for the scripts" and "needed by the skills" were two different things, and only the first was written down.
- New warnings, each naming the fix: world without `SUMMARY.md` (when it has entities) or `WORLD_ORDER.md` (stronger wording when stories use the world); `SUMMARY.md` out of step with the entity files, now by name (a renamed file with an unchanged count was invisible before; case and underscores are normalised so legacy `Some_Faction.md` vs `[[Some Faction]]` does not warn); a story not in `WORLD_ORDER.md`; a row naming a story that does not exist; a Complete row with no snapshot at that position; promoted chapters with no Timeline entry.
- Deliberately not errors: older projects legitimately lack these files and keep working. The router skill now relays the ones that affect the work and offers the named skill; it skips pure old-project quirks.
- Run against the author's real project: the two worlds without the files are reported, the populated world raises no false warning (its summary, order, snapshots and timelines are consistent), and the stories' chapter/timeline numbers agree.
- The two fixture-coverage hints ("no Book Series present", "no current_chapter") were noise for users; they now appear only in the repository's own `tools/check_layout_v1.py`. The synthetic fixture was completed (summary, world order, timeline entries) so it is a warning-free baseline; the one test that relied on it lacking a world order now removes the file in a temporary copy.
